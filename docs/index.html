RAG Tester

Audits RAG pipelines by checking whether retrieval actually did the work, not just whether the final answer was correct.

100% answer correctness
30.8% retrieval hit rate

Same run, same 13 questions. Every answer was right, but retrieval found the relevant passage for fewer than a third of them — the model was answering from what it already knew, and a correctness-only eval would never have noticed.

The problem

A RAG system can answer a question correctly while retrieving nothing useful for it. The model already knew the answer from its training data and never needed the context. Existing evaluation tools check only whether the final answer is correct, so they score this as a pass.

RAG Tester generates questions from your own corpus, records which chunk each answer came from, then runs your pipeline and checks two things independently: was the answer right, and was that chunk actually retrieved. Crossing the two gives four outcomes instead of one.

The four outcomes

Retrieved the right chunk
Did not
Correct
TRUE_PASS The pipeline worked. Retrieval found the source and the model used it.
LUCKY_PASS The answer is right and retrieval had nothing to do with it. Every other eval calls this a pass. This is the case the tool exists to find.
Wrong
GENERATION_FAILURE The right context was there and the model still got it wrong.
RETRIEVAL_FAILURE Wrong context, wrong answer. The honest failure.

For every LUCKY_PASS candidate, the question is re-asked with retrieval disabled entirely. If the answer is still correct, the verdict is confirmed rather than inferred.

Three runs from the bundled demo. The first two use an invented corpus whose facts exist nowhere else, so a correct answer has to have come from retrieval. The third uses facts any model knows cold.

Install and run

Python 3.11 or newer. Any OpenAI-compatible API works for the judge and generator.

pip install git+https://github.com/Aliismail293/rag-tester.git

Against your own corpus and adapter:

ragaudit ingest ./docs
ragaudit generate --n 100
ragaudit run --adapter my_adapter.py
ragaudit report --out report.html

Or run the whole bundled demo, three reports included:

docker compose up --build

An adapter is one function, query(question) -> RAGResponse, returning the answer, the retrieved chunk IDs, and the contexts. Your pipeline needs to be indexed against the chunks ragaudit ingest produced so the IDs line up; the README explains why.
